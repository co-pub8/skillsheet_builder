# スキルシート自動生成

YAML に書いた経歴データから、エンジニアのスキルシート（Word / PDF）を生成するツールです。

## 概要

スキルシートを Word で直接管理していると、案件が増えるたびに表の行を足したり、期間の月数を数え直したり、レイアウトが崩れたりと、内容以外の手間がかかりがちです。
このツールでは **「内容」と「見た目」を分けて管理** します。

| ファイル | 役割 | 編集方法 |
|---|---|---|
| `data.yaml` | 内容（職務要約・経歴・スキル・資格など） | テキストエディタ |
| `template.docx` | レイアウト（罫線・色・フォント・配置） | Word |
| `build.py` | 上の2つを組み合わせて .docx / .pdf を出力 | 通常は編集不要 |

```
data.yaml ─────┐
               ├─▶ build.py ──▶ output/【技術者コード】スキルシート_YYYYMM.docx (.pdf)
template.docx ─┘
```

### 主な機能

- **期間の自動計算** — 開始月・終了月から「2年3ヶ月」のような期間を算出します。終了月を省略すると「現在」まで（基準月は `--as-of` で指定可）として扱います。
- **開発経歴の起点を自動表示** — 見出しの「■開発経歴(YYYY年M月以降)」は、出力対象プロジェクトの最も古い開始月から決まります。
- **タグによる絞り込み** — 応募先に合わせて、`--tags` で特定分野のプロジェクトだけを載せたシートを作れます。
- **スキル表の自動整形** — 同じ区分（言語・FW・OS など）のセルを縦に結合し、「-」や空欄を中央揃えにします。
- **PDF 出力** — LibreOffice があればそれを使い、なければ Word（docx2pdf）で変換します。
- **入力チェック** — 日付形式の誤り、終了月が開始月より前、必須項目の欠落などをエラーメッセージで知らせます。

### 出力されるスキルシートの構成

1. ヘッダ（作成年月・技術者コード・所属）
2. 職務要約
3. 職務経歴
4. 開発経歴（プロジェクトごとに 概要 / 業務内容 / 実績 / 開発環境 / 役割 / 規模 / 担当工程）
5. スキルレベル（実務経験 / 実務以外での利用・学習歴）
6. 最終学歴
7. 保有資格
8. 自己PR
9. プライベートでの開発経験

## 動作環境

- Python 3.10 以降
- [docxtpl](https://docxtpl.readthedocs.io/)、PyYAML
- PDF を出力する場合は次のどちらか
  - LibreOffice（`soffice` にパスが通っていること）
  - Microsoft Word ＋ `docx2pdf`（Windows / Mac）

## セットアップ

```
pip install -r requirements.txt
pip install docx2pdf   # Word で PDF 変換する場合のみ
```

## 使い方

1. `data.yaml` を編集する（初期状態は架空人物のサンプルデータ）
2. `python build.py --pdf` を実行する
3. `output/【技術者コード】スキルシート_YYYYMM.docx / .pdf` が出力される

### オプション

| オプション | 説明 |
|---|---|
| `--pdf` | PDF も出力する（LibreOffice、または Word＋docx2pdf） |
| `--as-of 2026-10` | 作成年月と「現在」の基準月を指定する（省略時は今月） |
| `--tags 通信,組込み` | 指定したタグのいずれかを持つプロジェクトだけを出力する |
| `-d other.yaml` | 別のデータファイルを使う |
| `-t tpl.docx` | 別のテンプレートを使う |
| `-o out_dir` | 出力先フォルダを変える（既定は `output/`） |

### 実行例

```
python build.py                          # 今月時点のスキルシートを出力
python build.py --as-of 2026-10 --pdf    # 2026年10月時点として .docx と .pdf を出力
python build.py --tags Web,クラウド      # Web・クラウド案件だけに絞ったシートを出力
```

### 実データの置き場所

`_` で始まる YAML（例: `_data.yaml`）と `output/` は `.gitignore` で除外されています。
自分の経歴はサンプルの `data.yaml` をコピーした `_data.yaml` に書き、次のように実行すると、個人情報をコミットせずに済みます。

```
python build.py -d _data.yaml --pdf
```

## data.yaml の書き方

主な項目は次のとおりです。詳しくはサンプルの `data.yaml` 内のコメントを参照してください。

| 項目 | 必須 | 内容 |
|---|:---:|---|
| `engineer_code` | ○ | 技術者コード（出力ファイル名にも使われる） |
| `affiliation` | | 所属 |
| `duration_mode` | | 期間の数え方（`inclusive` / `exclusive`、後述） |
| `summary` | | 職務要約（1要素 = 1段落） |
| `careers` | ○ | 職務経歴（`from` / `to` / `org`）。`to: null` で在籍中 |
| `projects` | ○ | 開発経歴。上から順に出力される |
| `skills` | ○ | 区分ごとのスキル（`name` / `work` / `private`）。未経験は `"-"` |
| `education` | | 最終学歴（`date` / `text`） |
| `licenses` | | 保有資格（`date` / `name`） |
| `self_pr` | | 自己PR（`title` / `lines`） |
| `private_dev` | | プライベートでの開発経験（1要素 = 1行） |

プロジェクト 1 件の例:

```yaml
projects:
  - company: 株式会社サンプル (正社員)
    from: 2023-10
    to: null                 # null なら「現在」まで
    tags: [Web, クラウド]     # --tags での絞り込み用（任意）
    name: 社内向け 勤怠管理システムの開発
    overview:
      - 社内の勤怠管理をWeb化するシステムの開発
    work:
      - バックエンドAPIの開発(Python、FastAPI)
    achievements:            # 省略すると【実績・取り組み等】の欄ごと出力されない
      - ・〇〇を自動化し、作業時間を半分に短縮しました。
    env:                     # 見出し（OS・言語など）は自由に増減できる
      OS: [Linux]
      言語: [Python, TypeScript]
    role: リーダー
    size: 要員4名
    phases: [要件定義, 基本設計, 詳細設計, コーディング]
```

日付は `YYYY-MM`（例: `2019-04`）で書きます。`2019/4` の形式も受け付けます。

### 期間の数え方

`data.yaml` の `duration_mode` で切り替えます。

- `inclusive`（既定）: 開始月と終了月の両方を数える　例: 2019年4月～5月 = 2ヶ月
- `exclusive`: 差で数える　例: 2019年4月～5月 = 1ヶ月
- 個別に上書きしたい場合は、プロジェクトに `duration: "1ヶ月"` と書く

## レイアウトを変えたいとき

`template.docx` を Word で直接編集してください（罫線・色・フォントなど）。
`{{ }}` や `{%p ... %}` は差し込み用のタグなので、消さないでください。
タグを新しく書くときは、メモ帳で書いてから一度に貼り付けてください（Word が入力途中で文字を分割するのを防ぐため）。

`data.yaml` に新しい項目を追加した場合は、`build.py` の `build_context()` とテンプレートのタグの両方を合わせて変更する必要があります。

### 注意（Word で開けなくなるのを防ぐため）

- `w:vMerge` や `w:jc` など、XML の**属性値**には `{% %}` を書かないでください。
  Word は属性値を厳密にチェックするため、ファイルが開けなくなります。
  スキル表の縦結合と「-」の中央揃えは、`build.py` の `postprocess()` で差し込み後に設定しています。
- タグを書いてよいのは、**本文の文字**か、**段落・行だけに書く `{%p %}` / `{%tr %}`** だけです。
- スキル表は「4列で、見出しの2列目が `環境`」であることで識別しています。見出しの文言を変えると縦結合・中央揃えが効かなくなるので、変える場合は `build.py` の `_is_skill_table()` も合わせて直してください。

## ファイル構成

```
skillsheet_builder/
├── build.py              # 生成スクリプト本体
├── data.yaml             # 内容（サンプル: 架空人物）
├── template.docx         # レイアウト（docxtpl テンプレート）
├── requirements.txt
├── tools/
│   └── make_template.py  # 元のスキルシートから template.docx を作った変換スクリプト（通常は使わない）
└── output/               # 生成物の出力先（git 管理外）
```
